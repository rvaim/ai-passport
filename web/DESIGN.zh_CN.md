# Passport 网页安装器

## 用途

安装器用于把一个 `.pap` 插件或主题安装包，从桌面浏览器通过 Web Bluetooth 发送到附近的一台 Passport。两种包共用同一个页面和传输链路；所选文件只在浏览器和设备之间传输，不会上传。用户输入 Passport 上显示的公开配对码；浏览器按主广播中的 Passport Service UUID 发现设备，网页连接后读取 GATT 中公开的 Device Code，配对码不一致时拒绝目标设备。

## 本地运行

Web Bluetooth 要求安全上下文。localhost 会被视为安全环境，因此应启动本地服务，不能直接双击 HTML 文件：

```bash
python3 -m http.server 8000 --directory web
```

使用桌面版 Chrome 或 Edge 打开 `http://localhost:8000/installer.html`。Safari、Firefox 和 iOS 浏览器当前不提供 Web Bluetooth。

## 交互与视觉系统

页面只有一条线性任务路径：输入配对码、选择本地 `.pap` 插件或主题、连接匹配设备、开始安装。配对码输入过程中会规范化为大写的 `XXXXX-XXXXX-X`，因此粘贴、带空格或已经有横杠的内容都会走同一套校验。文件、目标设备、就绪状态、进度、设备反馈、失败恢复和完成结果始终可见，网页自身不使用弹窗。Web Bluetooth 首次由该网站访问设备时，浏览器拥有的强制授权窗口仍是必经步骤；之后，`navigator.bluetooth.getDevices()` 会提供已授权设备，网页会让广播名称与 `Passport-<code>` 完全相符的已授权设备直接重连，不再打开设备选择器；否则，浏览器会列出广播 Passport Service 的设备。网页在启用安装前会通过 GATT 校验完整配对码。GitHub Pages 直接把同一安装器部署为首页，不再提供包目录、独立主题入口或远程包预加载。键盘焦点、拖放、配对码无效、禁用、处理中、成功、失败、断开连接、浏览器不支持和非安全上下文等状态都有明确反馈。

视觉语言延续现有 Passport 安装器：浅蓝背景、深色文字、克制的蓝色操作控件、单一清晰边框容器、12～16 px 圆角和中性偏移阴影。本地配置工具不下载网页字体，使用系统字体以减少等待和外部依赖。SVG 图标采用一致描边，状态不会只靠颜色表达。

## Agent 授权 Demo

授权 Demo 延续同一个本地 Passport 网页工具，但提供第二条实时监控流程。它假定设备上的 Agent 授权面板已经打开，并把连接状态、可编辑请求、最终载荷预览、响应和事件记录放在同一个界面中。请求编辑区保持紧凑，因为核心决策是载荷本身；右侧监控区则为连接和发送状态提供稳定的视觉位置。

Demo 继承安装器的配色和字号体系：浅蓝画布、深色文字、克制的蓝色主操作、中性 elevation 和系统字体。主要状态包括未连接、连接中、已连接、发送中、收到响应和错误。发送请求是最强操作，连接设备和取消当前请求保持为明显的次级操作。移动端折叠为单列，同时保留发送前的载荷预览。

## 协议与限制

页面只接受非空且不超过 4 MiB 的 `.pap` 文件，会校验并规范化输入的配对码、按主广播中的自定义 Service UUID 发现设备、复核 GATT 返回的设备码、在本地计算 IEEE CRC-32，并以 180 字节分片进行有响应写入和有界重试。按 Service 发现延续了固件提交 `9d27ed8` 中已经验证的安装器行为，不依赖浏览器先合并主广播与 scan response 再执行筛选。页面会等待设备返回开始接收和最终安装通知。纯协议 helper 由 `tests/test_web_installer_protocol.mjs` 覆盖，并纳入仓库静态门禁。
